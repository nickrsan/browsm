## 1. Input Prompt & Problem Understanding

The user requested to proceed with implementing each phase of the plan with pauses after each phase to commit files to the local git repository.

Phase 3 focuses on:
1. **In-Page Structured Data (Schema.org / Microdata) Extraction**: Content scripts extracting JSON-LD (`@graph`, arrays, direct objects), HTML5 Microdata (`itemscope`, `itemtype`), and OpenGraph fallbacks from visited web pages, signaling presence via action toolbar badging and custom tooltips.
2. **Tag Normalization Engine**: Sanitizing extracted metadata into standard OpenStreetMap tagging conventions (`addr:*`, phone in E.123 format, clean website URLs, `opening_hours`, and category mappings).
3. **Cached Nominatim Geocoding**: Structured and free-form address lookup with a 24-hour local storage cache (`browser.storage.local`) and User-Agent compliance.
4. **Spatial Matching & Bounding-Box POI Retrieval**: Querying OpenStreetMap API 0.6 (`/api/0.6/map?bbox=...`) for a 50m micro-bounding box, parsing nodes and building structures (`way` polygons with centroids), scoring candidates using Sørensen-Dice name similarity and proximity, and generating tag diffs.
5. **Direct Sidebar Search & Browse Mode**: Providing in-sidebar search input and listing nearby POIs and structures.
6. **Popup Place Inspector**: Compact popup interface displaying detected place details with a 1-click verification shortcut.

## 2. Actions Taken & Code Generated

### Modules & Services Created:
1. **`src/services/schema-parser.ts`**:
   - Parses `<script type="application/ld+json">` supporting `@graph`, arrays, and nested places.
   - Parses HTML5 Microdata `[itemscope]` with `[itemprop]` fields.
   - Extracts OpenGraph meta tags as supplementary fallback.
   - Normalizes into strongly-typed `SchemaOrgPlace` structures.
2. **`src/services/tag-normalizer.ts`**:
   - Converts Schema.org categories (`Restaurant`, `Bakery`, `Hotel`, `Pharmacy`, etc.) to primary OSM tags (`amenity`, `shop`, `tourism`, `healthcare`).
   - Splits house numbers and street names into `addr:housenumber` and `addr:street`.
   - Formats phone numbers into international E.123 standard format.
   - Validates and normalizes website URLs with `https://`.
   - Formats opening hours into OSM-compatible semicolon-delimited strings.
3. **`src/services/geocoding.ts`**:
   - Implements `geocodeQuery` and `geocodeStructured` querying Nominatim.
   - Enforces descriptive User-Agent header per API acceptable use policy.
   - Implements local storage caching with 24-hour TTL (`CACHE_TTL_MS = 86,400,000`).
4. **`src/services/spatial-matcher.ts`**:
   - Computes 50m radius bounding boxes (`calculateBboxAroundCoords`).
   - Fetches live OSM API 0.6 XML and parses nodes and way building polygons (`parseOsmBboxXml`).
   - Implements candidate scoring (`findBestMatch`) using Sørensen-Dice string similarity, distance metrics, phone, and website matches.
   - Produces structured tag comparison items (`generateTagDiff`).
5. **`src/entrypoints/content/index.ts`**:
   - Content script running at `document_idle`.
   - Scans DOM for structured markup and sets up a debounced `MutationObserver` to detect dynamic SPA injections.
   - Transmits `schemaDetected` messages to background.
6. **`src/entrypoints/background.ts`**:
   - Handles `schemaDetected` by setting green `POI` action badges and descriptive titles.
   - Handles `check-address` context menu selections via geocoding and bounding-box spatial inspection.
   - Handles `searchPoi` messages from sidebar and popup.
7. **`src/entrypoints/sidebar/Sidebar.svelte` & `src/entrypoints/popup/App.svelte`**:
   - Enhanced sidebar with direct search input, detected page schema alert banner, and nearby POI/structure listings.
   - Built popup place card with verification trigger.
