# Task Summary Report: Storage DataCloneError Fix and OSM API Anti-Abuse Rate-Limiting Safeguards

**Date & Time**: 2026-11-16 22:15  
**Report File**: `summary_2026-11-16_22-15.md`

---

## 1. Input Prompt
> The addon is repeatedly through an error "Error saving auth state for osm-dev to storage: Error: DataCloneError: Proxy object could not be cloned", then firing off another request to the API /user/details page and getting stuck in a loop. Please fix the error and also ensure we don't abuse the API on error

---

## 2. Understanding of the Issue

Two interrelated issues were identified in the authentication storage and message polling architecture:
1. **`DataCloneError: Proxy object could not be cloned`**:
   - In Svelte 5 runes (`$state`), state objects are wrapped in JavaScript `Proxy` instances.
   - When saving authentication state to `browser.storage.local.set()`, Firefox's XPCOM WebExtension IPC structured clone algorithm throws a `DataCloneError` when encountering reactive `Proxy` objects.
2. **Infinite Cascading API Loop & Lack of Error Backoff**:
   - In `Sidebar.svelte`, the `$effect` managing periodic message polling synchronously read reactive properties (`authStore.isAuthenticated`, `authStore.token`, `authStore.user`) during its initial execution.
   - When `refreshUserDetails()` was invoked, updating `authStore._authStates` (or writing to storage) marked the effect dirty in Svelte 5, re-running the effect and triggering `refreshUserDetails()` repeatedly in an immediate synchronous loop.
   - There was no in-flight request deduplication, rate-limiting cooldown, or error backoff protecting OpenStreetMap servers against cascading requests during transient errors or rate limits (HTTP 429).

---

## 3. Actions Taken & Code Generated

### 1. Plain POJO Serialization for Storage (`src/services/osm-auth.ts`, `src/stores/settings.svelte.ts`)
- Updated `saveStoredAuthState()` to serialize state via `JSON.parse(JSON.stringify(state))` into a clean plain JavaScript object before passing it to `browser.storage.local.set()`.
- Updated `settingsStore.persist()` similarly to eliminate any possibility of Proxy objects reaching WebExtension storage APIs.

### 2. Untracked Polling Effect (`src/entrypoints/sidebar/Sidebar.svelte`)
- Wrapped the message polling execution with Svelte 5 `untrack(() => ...)` so that reads of `authStore` inside `checkMessages` / `poll` do not register as reactive dependencies of the `$effect`.
- The effect now re-initializes only when the configured polling interval or active authentication state genuinely transitions, preventing recursive loops.

### 3. Anti-Abuse & Rate-Limiting Protections (`src/stores/auth.svelte.ts`)
- **In-flight request deduplication**: Uses `_inFlightRefresh` to share a single pending promise across concurrent calls for the same target endpoint.
- **Cooldown throttling**: Enforces a minimum 30-second interval (`MIN_REFRESH_INTERVAL_MS = 30000`) between successive API calls per endpoint unless explicitly forced.
- **Exponential error backoff**: Automatically backs off on errors (1 min, 2 min, 4 min, 8 min, up to 15 min max) to prevent hammering failing or offline servers.
- **HTTP 429 rate limit backoff**: Detects HTTP 429 responses and enforces an automatic 5-minute backoff window (`_rateLimitResetTime`).
- **Reactive change diffing**: Compares new user metadata with existing state and only updates reactive stores and local storage if data has actually changed.
- **Storage listener deduplication**: In `authStore.init()`, checks for deep equality before assigning state to prevent cascading UI updates.

### 4. Typed Error Handling (`src/services/osm-api.ts`)
- Introduced `OsmApiError` exporting the HTTP `status` code for granular handling of 401, 403, 429, and 500 responses.

### 5. Automated Tests & Documentation
- Added 5 new unit tests in `tests/unit/osm-messages-polling.test.ts` verifying:
  - Proxy object persistence without `DataCloneError`.
  - Polling throttling and cooldown enforcement.
  - In-flight request deduplication.
  - Exponential error backoff on HTTP 500/network failures.
  - 5-minute backoff on HTTP 429 rate limit errors.
- Added non-looping verification test in `tests/unit/sidebar.test.ts`.
- Updated `FEATURES.md` and `documentation/developer_api.md`.
