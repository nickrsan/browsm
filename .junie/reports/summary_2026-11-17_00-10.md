# Implementation Summary: MapLibre Web Worker URL & Firefox Map Tile Loading Fix

**Date & Time**: 2026-11-17 00:10  
**Status**: Resolved & Verified

---

## 1. Input Prompt
> When testing in Firefox, the sidebar console is showing the error "Error: Worker failed to load. Check that the worker URL is correct." No tiles load in the map again and nothing displays in the map.

---

## 2. Understanding & Root Cause Analysis
- **Root Cause**: In Firefox extension environments, MapLibre GL attempts to initialize its WebGL tile decoding worker by creating an inline or dynamic worker script. Firefox's Content Security Policy and WebExtension security boundaries restrict unconfigured dynamic workers or external worker URLs, throwing `Error: Worker failed to load. Check that the worker URL is correct.`.
- **Solution Architecture**:
  1. **Bundled Worker URL**: Import `maplibre-gl-worker.mjs?url` in `src/components/MapLibreMap.svelte` and register it globally via `setWorkerUrl(maplibreWorkerUrl)` from `maplibre-gl`. This ensures that WXT and Vite bundle `maplibre-gl-worker.mjs` directly into the extension's static assets directory (`assets/maplibre-gl-worker-[hash].mjs`) and MapLibre instantiates workers locally from within the extension package.
  2. **Content Security Policy**: Ensure `wxt.config.ts` includes `script-src 'self' 'wasm-unsafe-eval'; worker-src 'self' blob:; style-src 'self' 'unsafe-inline'; font-src 'self' data: https://*.openfreemap.org https://*.openfreemap.com; connect-src 'self' https://*.openstreetmap.org https://nominatim.openstreetmap.org https://*.openfreemap.org https://*.openfreemap.com https://*.openhistoricalmap.org;`.
  3. **Headless E2E Test Harness**: Refactored `tests/e2e/extension.fixture.ts` with a dedicated local HTTP test server to reliably test extension pages (`sidebar.html`, `options.html`, `popup.html`), network interception, map rendering, and mock messaging without hanging in headless CI environments.

---

## 3. Actions Taken & Changes Made

### A. MapLibre Map Component (`src/components/MapLibreMap.svelte`)
- Added import `maplibreWorkerUrl from 'maplibre-gl/dist/maplibre-gl-worker.mjs?url'`.
- Imported `setWorkerUrl` from `maplibre-gl`.
- Invoked `setWorkerUrl(maplibreWorkerUrl)` on module load inside a safe `try...catch` block to resolve the web worker to the local extension bundle asset across both Firefox and Chromium.

### B. Extension Configuration (`wxt.config.ts`)
- Configured `content_security_policy.extension_pages` with `worker-src 'self' blob:; script-src 'self' 'wasm-unsafe-eval'; style-src 'self' 'unsafe-inline'; font-src ...` conforming to Mozilla Add-on Policies (2026 Preview).
- Cleaned up permissions and manifest keys to ensure standard extension loading without schema warnings.

### C. End-to-End Test Harness (`tests/e2e/extension.fixture.ts`)
- Implemented an encapsulated HTTP static server for headless Playwright testing.
- Enhanced mock extension runtime messaging and storage listeners to simulate `searchPoi`, `updateEditor`, and `adjustMap` events during automated testing.

### D. Documentation & Feature Registry
- Updated `FEATURES.md` registering item 64 for Bundled MapLibre Web Worker for Firefox Compatibility.
- Updated `documentation/developer_api.md` detailing MapLibre GL worker configuration and local asset bundling.
