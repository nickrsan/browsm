### 1. Input Prompt & Problem Understanding
**User Prompt**:
> "That last set of changes looks good, but I'm wondering if we need to also have the extension look for an item in the dev API after querying nominatim. It fails to get the correct Node ID when using the OSM Dev API, so it always fails to update the node. It'd be good if Nominatim helped us find the general location, then we confirm and find the correct node/POI information via the API"

**Understanding**:
1. OpenStreetMap's Nominatim geocoding service (`nominatim.openstreetmap.org`) indexes and reflects the live OpenStreetMap production database.
2. When searching for an address or place name while configured with the OSM Dev API (`https://master.apis.dev.openstreetmap.org/api/0.6`) or a custom server, Nominatim returns a production Node ID (`osm_id`).
3. If the extension attempted to update that production Node ID against the Dev API sandbox, the request resulted in HTTP 404 Not Found because the entity does not exist on the Dev API server.
4. The solution requires a multi-stage resolution pipeline:
   - Use Nominatim purely to resolve the general geographic location (`lat`, `lon`, place name query).
   - Resolve the active target OpenStreetMap API endpoint (Dev API, Production, or Custom) from settings.
   - Query the active API server via bounding box (`GET /api/0.6/map?bbox=...`) to retrieve the actual nodes and structures present on that specific server.
   - Match and score candidates against the elements retrieved from the active API server. If a match is found on the active server, select its real server-specific ID, version, and tags.
   - If no match exists on the active server (or when targeting non-production environments where the production ID does not exist), do not use the production `osm_id`. Instead, cleanly present the location as a **New POI Candidate** (`selectedElement = null`), ensuring that subsequent changeset submissions execute standard node creation (`POST /nodes` / `PUT /node/create`) on the active server without 404 update errors.
