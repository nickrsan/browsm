# Implementation Summary: Changeset Lifecycle, PMTiles Protocol, and Popup Resiliency

**Date**: 2026-11-16 21:55  
**Topic**: Changeset Auto-Close Guarantee, MapLibre PMTiles Protocol Registration, and Popup State Hydration Fix

---

### 1. Input Prompt & Problem Understanding

The user reported three key items during testing:
1. **Unclosed Changesets**: Changesets were remaining open on OpenStreetMap after editing rather than being closed upon completion.
2. **PMTiles Vector Tile Support**: While MapLibre loaded Natural Earth raster/base tiles, vector tiles hosted in `.pmtiles` format (such as OpenFreeMap vector tile archives) were not being decoded by MapLibre.
3. **Popup Rendering Failure**: The extension action popup was failing to display properly on active web pages while the sidebar remained functional.

---

### 2. Root Cause Analysis & Actions Taken

#### Item 1: Guaranteed Changeset Closure (`src/components/ChangesetModal.svelte` & `src/services/osm-api.ts`)
- **Root Cause**:
  - In `ChangesetModal.svelte`, `closeChangeset` was previously positioned sequentially after element create/update operations without a `try...finally` safety wrapper.
  - If any intermediate network glitch or version conflict occurred during `updateNode` or `createNode`, execution jumped directly to the outer `catch` block, leaving the open changeset dangling on OpenStreetMap.
  - Furthermore, `createdChangesetId` was assigned immediately after `createChangeset`, which prematurely flipped the UI to the success view even if subsequent operations failed.
- **Solution**:
  - Encapsulated the element create/update operation inside a `try...finally` block that guarantees `closeChangeset` is dispatched immediately before exiting.
  - Enhanced `closeChangeset` in `src/services/osm-api.ts` to idempotently handle HTTP 409 responses if the server has already closed the changeset.
  - Deferred setting `createdChangesetId` until all operations succeed, ensuring that any upload failure properly displays the error message and recovery options.

#### Item 2: MapLibre PMTiles Vector Tile Archive Protocol (`src/components/MapLibreMap.svelte`)
- **Root Cause**:
  - OpenFreeMap vector styles and custom PMTiles archives utilize the `pmtiles://` custom URL protocol.
  - MapLibre GL JS requires registering a protocol handler via `addProtocol('pmtiles', pmtilesProtocol.tile)` from the `pmtiles` library so the vector tile worker can decompress PMTiles archives.
- **Solution**:
  - Imported `* as pmtiles` in `src/components/MapLibreMap.svelte` and globally registered `pmtiles.Protocol` with MapLibre via `addProtocol('pmtiles', pmtilesProtocol.tile)`.
  - Added unit tests in `tests/unit/maplibre-map.test.ts` verifying protocol registration.

#### Item 3: Extension Popup State Hydration & Viewport Styling (`src/entrypoints/popup/` & `src/entrypoints/background.ts`)
- **Root Cause**:
  - In `src/entrypoints/background.ts`, `openSidebar` previously had a fallback call `browser.action.setPopup({ popup: 'sidebar.html' })` which inadvertently overwrote the browser action popup target with the sidebar page.
  - `src/entrypoints/popup/app.css` retained default Vite boilerplate centering (`body { min-height: 100vh; display: flex; place-items: center; }`), causing viewport layout collapse in extension popups.
  - `src/entrypoints/popup/App.svelte` previously only checked global `currentSchema` without checking tab-specific storage (`tab_schema_${tabId}`).
- **Solution**:
  - Removed the erroneous `setPopup({ popup: 'sidebar.html' })` override in `background.ts`.
  - Modernized `src/entrypoints/popup/app.css` and `src/entrypoints/popup/index.html` with clean 320px fixed-width popup styles, box-sizing resets, and full light/dark mode CSS variables.
  - Updated `App.svelte` `onMount` lifecycle to query both tab-specific schema storage (`tab_schema_${activeTabId}`) and global fallback state.
