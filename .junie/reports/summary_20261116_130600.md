### Understanding of the Task
The task was to implement the **Multi-Endpoint and Developer Mode Configuration System** for `browsm` according to the execution plan (`.junie/plans/multi-endpoint-and-dev-mode-settings.md`):
1. **Endpoint Presets & Settings Data Models**: Define types and configurations for OpenStreetMap Live (`osm-prod`), OSM Dev Sandbox (`osm-dev`), OpenHistoricalMap (`openhistoricalmap`), and Custom Instances, and expand manifest host permissions to include `https://*.openhistoricalmap.org/*` in compliance with Mozilla Add-on Policies.
2. **Multi-Target OAuth Service, Token Isolation & Dynamic Endpoint Resolver**: Implement isolated token management per endpoint in `browser.storage.local` (`browsm_auth_<endpointId>`) with legacy key migration, create a centralized endpoint resolver (`resolveApiEndpoint`) supporting Granular Developer Mode routing (`writes_only` read/write split and `reads_and_writes` full sandbox), and build the reactive Svelte 5 `settingsStore` and `authStore`.
3. **Options Page & Quick-Settings Modal**: Build a full WebExtension options page (`src/entrypoints/options/Options.svelte`) and embedded quick-settings modal (`src/components/SettingsModal.svelte`) for instant environment switching.
4. **Visual Environment Badges & Documentation**: Integrate visual badges in the sidebar and popup headers (`[DEV: WRITES ONLY]`, `[DEV: FULL]`, `[OHM]`, `[CUSTOM]`), parameterize `AuthHeader.svelte` for target-specific authentication, update `FEATURES.md`, `README.md`, `documentation/user_guide.md`, and `documentation/developer_api.md`, and verify with automated unit and component test suites.

## 2. Actions Taken & Code Generated

### 1. Data Models & Manifest Permissions (`Step 1`)
- Created `src/types/settings.ts` defining `EndpointPreset`, `DevModeRouting`, `PreferredEditor`, `EndpointConfig`, `SettingsState`, and `ResolvedEndpoint`.
- Populated `ENDPOINT_PRESETS` with official URLs, OAuth 2.0 endpoints, and scopes for OSM Production, OSM Dev Sandbox (`master.apis.dev.openstreetmap.org`), OpenHistoricalMap, and custom configurations.
- Added URL sanitization (`sanitizeEndpointUrl`) and configuration validator (`validateEndpointConfig`).
- Updated `wxt.config.ts` declaring `https://*.openhistoricalmap.org/*` in `host_permissions` alongside existing OSM and Nominatim domains in full accordance with Mozilla Add-on Policies.
- Created `tests/unit/settings-types.test.ts` verifying presets, fallback resolution, and sanitization logic.

### 2. Multi-Target Authentication & Dynamic Endpoint Resolver (`Step 2`)
- Refactored `src/services/osm-auth.ts` to namespace credentials per endpoint (`browsm_auth_<endpointId>`) with transparent backwards-compatible migration from legacy `browsm_osm_auth_state`.
- Created `src/services/endpoint-resolver.ts` providing `resolveApiEndpoint('read' | 'write')` and `resolveEndpointSync` to dynamically route reads and writes based on `DevModeRouting` flags (`writes_only` routes reads to live OSM production and test edits safely to OSM Dev sandbox).
- Created reactive Svelte 5 `src/stores/settings.svelte.ts` backed by `browser.storage.local` and listening for cross-context storage changes.
- Updated `src/stores/auth.svelte.ts` to manage multi-endpoint session states, resolve the active write target in developer mode, and support per-target login/logout without overwriting tokens.
- Parameterized `fetchOsmElementsInBbox` in `src/services/spatial-matcher.ts` to accept dynamic API base URLs.
- Created unit tests in `tests/unit/endpoint-resolver.test.ts`, `tests/unit/osm-auth-multi.test.ts`, and `tests/unit/settings-store.test.ts`.

### 3. Options Page & Sidebar Quick-Settings Interface (`Step 3`)
- Created `src/entrypoints/options/` with `index.html`, `main.ts`, and `Options.svelte` offering a full settings dashboard with Developer Mode toggles, preset selectors, custom server configuration form, and multi-endpoint account manager.
- Created `src/components/SettingsModal.svelte` providing an accessible overlay for instant environment and developer mode switching directly from the Sidebar and Popup.
- Integrated gear action button (`⚙️`) in `src/entrypoints/sidebar/Sidebar.svelte` and `src/entrypoints/popup/App.svelte`.
- Created component tests in `tests/unit/options-page.test.ts`.

### 4. Visual Badges, Verification & Documentation (`Step 4`)
- Added visual environment status badge indicators in `Sidebar.svelte` and `App.svelte` headers with high-contrast color coding (`[DEV: WRITES ONLY]`, `[DEV: FULL]`, `[OHM]`, `[CUSTOM]`) and explanatory tooltips.
- Updated `AuthHeader.svelte` to display the active target endpoint name, badge, and sandbox mode hints, and prompt for login against the specific active target.
- Updated `tests/unit/auth-header.test.ts` with developer mode and target reflection assertions.
- Updated `FEATURES.md`, `README.md`, `documentation/user_guide.md`, and `documentation/developer_api.md`.
